**Testing Conventions**

- Prefer e2e tests for behavior that crosses a process or I/O boundary (CLI flags, config loading, git operations, agent spawning, daemon coordination, stdout/stderr, recorded fixtures); unit-test pure helpers where speed and failure localization matter. Prefer creating real git repos in temp dirs over heavy mocking.
- The e2e suite is behind the `e2e` build tag; `make e2e` runs `scripts/e2e.sh`, which sweeps `./internal/e2e/...` and `./internal/pipeline/steps/...` in one process under a 720s cap, so keep new step-local e2e tests behind the tag too.
- `internal/e2e` tests cannot use `t.Parallel` (each harness sets process-wide env with `t.Setenv`), so CI splits the package across runners instead: `scripts/e2e.sh --shard <i>/<n>` runs every n-th top-level test in name order from `go test -list`, and shard 1 also runs the steps packages, each `go test` under a 480s cap. The shard is the top-level test, so a new journey worth more than a few percent of the package's time is its own top-level test, as `TestUserJourney<Agent>` is one per agent. Regressions: `TestE2EScriptShardsDealEveryTestOnce` and the other `TestE2EScript*` tests.
- An e2e test that needs a run held active (to check something against it) holds it on the fake agent's `release_file` scenario field and creates the file when its check is done, never a `delay_ms` sized to outlast the check. The TUI pty driver (`internal/e2e/testdata/tui_yolo_driver.py`) answers the TUI's startup terminal queries (OSC 11, CSI 6n), which otherwise each wait out termenv's 5s timeout, and sends its keys once a given text is drawn.
- Temporary e2e daemons (`NM_TEST_START_DAEMON=1` / harness) are owned by `internal/e2edaemon`: exact inventory, concurrency cap (`NM_E2E_DAEMON_MAX`, default 2), bounded argv checks, and reapers in harness Cleanup, package `TestMain`, and `scripts/e2e.sh` EXIT/INT/TERM. The package `TestMain` reaps with `ReapOrphaned`, which leaves entries another live process owns, because two `go test` runs of `./internal/e2e` without the wrapper share the default inventory and a `ReapAll` there stopped the other run's live daemons; the wrapper keeps `ReapAll` for its own per-invocation inventory. A SIGKILL of the wrapper shell does not run its trap; next-run inventory recovery covers that. External sleep-loop keepalives are out of scope. Never point inventory reaping at the shared `~/.no-mistakes` service. Regressions: `internal/e2edaemon/*_test.go`.
- A full temp filesystem (or a user quota on `/tmp`) fails an e2e test in shapes that do not name it: a git command exiting 128, a run that failed before any step, a run left `running` until the wait times out because the daemon cannot write the failure to its database either. The harness therefore ends a failed test with a `DISK FULL:` line when a command it ran, or a log under the test's `NM_HOME`, carries an ENOSPC, EDQUOT or SQLITE_FULL sign (`internal/e2e/disk_full.go`); read that line before chasing the failure above it. A second harness cleanup fails a test whose launched daemon still runs after shutdown (`internal/e2e/daemon_exit.go`).
- Packages whose tests shell out to git unset `GIT_CONFIG_COUNT` in `TestMain` so ambient `GIT_CONFIG_*` injection from agent harnesses cannot leak in; a test exercising injected config re-sets it with `t.Setenv` (see `internal/git`, `internal/gate`, `internal/daemon`, `internal/pipeline/steps`, `internal/pipeline/steps/citest`, `internal/pipeline/steps/internal/stepstest`).
- Packages whose tests can start a daemon or touch ambient state (`cmd/no-mistakes`, `internal/cli`, `internal/update`) point `NM_HOME` and `HOME` at fresh temp dirs in a package-wide `TestMain` through `internal/testhome` (`testhome.Setup`, then `os.Exit(dirs.Close(code))`), and set their own telemetry/update-check variables and stop their own daemon, so a full test run never touches a real `~/.no-mistakes`. Use the same helper in a new such package. `testhome` owns the throwaway HOME's whole life: before `HOME` moves it exports `GOMODCACHE`, `GOCACHE` and `GOPATH` at the toolchain's own values (all default under `HOME`, so a test's `go build` once extracted a fresh read-only module cache into it, about 380 MB a run, whose `os.RemoveAll` failed unseen until `/tmp`'s quota was gone), it writes Go's telemetry mode as `off` inside the new `HOME` (every `go` command otherwise writes counters there and starts a detached upload sidecar that can recreate the `HOME` after its removal), and `Close` makes every tree writable before it removes it and prints `testhome: could not remove <dir>: <error>` when it still cannot. Off Windows that failure also turns a passing run red, because it is then a real leak; on Windows a daemon still exiting can hold a file for a moment, so there the line is the whole report. `NM_TEST_TMP_BASE` overrides the directory both are made in (`internal/cli` uses `/tmp` off Windows for its short socket paths, the others the system temp dir), which is how a test points a child run of its own test binary at a directory it can inspect. Regressions: `internal/testhome/testhome_test.go`, `TestTheTestHomeIsRemovedWithAReadOnlyTreeInIt`, `TestGoBuildsKeepTheirCachesOutsideTheTestHome`.
- A test helper removes what it makes in the temp dir by the end of the run, because a passing run that leaves a directory behind repeats it on every run until `/tmp`'s quota is gone. A per-process cache goes in the cleanup its `TestMain` already runs: the git template repo `stepstest.SetupGitRepo` copies from (one owner for `internal/pipeline/steps` and `steps/citest`) is removed by the cleanup `stepstest.Init` returns. A copy of the test binary that a test re-executes never reaches its `TestMain` cleanup (the test kills it, or it exits in flag parsing on a CLI-only flag such as `--update-check`), so that child makes nothing: `internal/update`'s `TestMain` marks its environment with `NO_MISTAKES_UPDATE_TEST_PARENT=1`, and a process that inherits the mark runs on its parent's `NM_HOME` and `HOME`. Regressions: `TestInitCleanupRemovesTheGitRepoTemplate`, `TestAReExecutedTestBinaryLeavesNothingInTheTempDir`.
- `paths.New()` refuses the default `~/.no-mistakes` root under `go test`; tests that touch app state must set `NM_HOME` to a temp dir, and only the production-default path test may opt in with `NO_MISTAKES_ALLOW_DEFAULT_ROOT_IN_TESTS=1`.
- Isolate filesystem and environment state with `t.TempDir()` and `t.Setenv()`.
- CI (`.github/workflows/ci.yml`) runs on Linux only: `check` (gofmt and `go vet`), `test (ubuntu-latest)` (`go test -race ./...` and a build) and `e2e`, on pull requests to `main` or started by hand (`workflow_dispatch`). The `e2e` check is a roll-up: it runs after the `e2e shard <i>/3` matrix jobs whatever they concluded and passes only when every shard passed, so the one check name stays while the suite runs on three runners; the matrix over `shard` is the only one in the workflow. No CI job runs on macOS or Windows, so a macOS- or Windows-only code path gets no CI run, and a test comment about a macOS or Windows cost names the host platform, never a CI job. Every run's token is read-only (`permissions: contents: read`), since no job writes to GitHub. Regressions: `TestCIWorkflowRunsOnLinuxOnly`, `TestCIWorkflowE2EShardsRollUpIntoTheE2ECheck`, `TestCIWorkflowCanBeStartedByHand`, `TestCIWorkflowTestJobRunsTheRaceSuiteAndBuilds`, `TestCIWorkflowTokenIsReadOnly`.
- On a Windows host the test suite is process-spawn bound, not compute bound: git-backed packages cost roughly 10x their Linux time (`internal/git` 5.7s -> 53s, `internal/branchsync` 31s -> 415s), which is what Windows-only test timeouts and budgets such as `internal/branchsync`'s fetch budget and the Windows timeouts in `waitForRunTerminalState` and `internal/daemon/manager_test.go` are sized for.
- Go applies an implicit GOOS constraint from a filename suffix, so a test file named `*_windows_test.go` (or `_linux`, `_darwin`) silently compiles only on that platform. Name platform-agnostic tests about Windows something else.
- On macOS with Go 1.26.0-1.26.4, a git-heavy package under `-race` intermittently loses a git child before it runs git: darwin `syscall.rawSyscall` was race-instrumented, and `forkAndExecInChild` calls it in the forked child before `execve` ([golang/go#79804](https://github.com/golang/go/issues/79804), fixed in Go 1.26.5). It surfaces as `git <cmd>: signal: segmentation fault`; `exit status 66` with empty stderr beside a bare `ThreadSanitizer: CHECK failed: tsan_rtl.cpp:94 "((part)) == ((part1))"` line; `exec: WaitDelay expired before I/O complete` from a git that exited 0 (a wedged sibling child still holds its inherited pipe); or goroutines parked in `syscall.forkExec` -> `readlen` until the package timeout. Code that folds a git error into a verdict then fails a test (branchsync's `blocked_assumptions_changed` with relation `unknown`). None of it is a repo bug: check `go version` and upgrade the toolchain rather than adding retries, waits, or longer timeouts. `~/Library/Logs/DiagnosticReports/*.ips` records the crash as `procName: <pkg>.test, parentProc: <pkg>.test, asi: "crashed on child side of fork pre-exec"`; CI runs on Linux only, so no CI job hits it. The same bug explains a stray `<pkg>.test -test.timeout=...` process at high CPU that ignores its own deadline: it is a pre-exec child spinning in `__tsan::TraceSwitchPartImpl` that inherited the parent's name, argv, and cwd, so no test-side timeout applies to it. `internal/procreap` reaps those by cwd.

**Pipeline step tests (CI latency)**

- Fake `gh`/`glab`/`git` on PATH must be the tiny helper at `internal/pipeline/fakecli`, compiled once per test process without `-race` (`stepstest.Init` / `LinkFakeCLI`). Tests that need the underlying Git binary use `internal/testgit.RealGit`, which resolves fixed absolute locations without consulting PATH. Do not re-exec the race-instrumented test binary as those names: that was ~0.8-1.1s per spawn and pushed `internal/pipeline/steps` into the 10-minute package timeout.
- CI-monitor tests live in `internal/pipeline/steps/citest` so no child of `internal/pipeline/steps` sits near that cap. Both packages run under `go test ./...`; do not move them behind the `e2e` tag.
